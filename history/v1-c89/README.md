# Учебный компилятор подмножества Java в ANSI C89 (ISO C90)

Компилятор на Python 3.10+ переводит программы на Java-подобном языке в исходный код
ANSI C89 / ISO C90. Сгенерированный код собирается вместе с runtime-библиотекой на C89
компилятором GCC MinGW-w64 для Windows x86-64.

Это полноценный компилятор: лексический, синтаксический и семантический анализ, анализ
потока управления, типизированное промежуточное представление (IR), генерация C и
runtime со сборкой мусора. Язык отличается от Java намеренно: множественное
наследование классов, единый `Object`, полный запрет неявных преобразований.

## 1. Требования и установка

| Компонент | Требование |
|-----------|------------|
| Python | 3.10 или новее (проверено на 3.12.10). Только стандартная библиотека, сторонних зависимостей нет |
| C-компилятор | GCC MinGW-w64 для `x86_64-w64-mingw32` (проверено: GCC 16.2.0, UCRT), доступный как `gcc` в `PATH` |
| Платформа | Windows x86-64 |

Установка не нужна: достаточно скопировать каталог проекта. Все команды запускаются из
корня проекта.

Модули стандартной библиотеки и зачем они нужны: `unicodedata` — классы символов
идентификаторов, `fractions` — точное округление вещественных литералов, `struct` —
битовые представления IEEE 754, `subprocess` — вызов GCC.

## 2. Запуск: генерация C и сборка

Генерация C и компиляция C — два отдельных этапа.

**Генерация C:**

```bash
python -m compiler.main examples/Diamond.java -o diamond.c
```

Команда создаёт `diamond.c` и `diamond.h`. Дополнительные опции:

| Опция | Назначение |
|-------|------------|
| `-o NAME.c` | имя выходного файла (`.h` создаётся рядом) |
| `--out-dir DIR` | каталог для выходных файлов |
| `--main Class` | класс с точкой входа, если в наборе исходников их несколько |
| `--debug` | traceback для внутренних ошибок компилятора |

Можно передать несколько исходных файлов: они образуют единый набор исходников с общей
таблицей типов.

**Сборка исполняемого файла:**

```bash
python -m compiler.build diamond.c -o diamond.exe
```

Эта команда эквивалентна вызову:

```bash
gcc -std=c89 -pedantic-errors -Wall -Wextra -O0 -I runtime diamond.c runtime/*.c -o diamond.exe -lshell32 -lm
```

`-std=c89 -pedantic-errors` применяется ко всем файлам, включая платформенные модули.
`-O0` обязателен для консервативного GC (§9).

**Коды завершения компилятора:** `0` — успех, `1` — ошибки в исходной программе,
`2` — ошибка командной строки или ввода-вывода, `3` — внутренняя ошибка компилятора.
**Код завершения программы:** `0` — нормальное завершение, `1` — runtime error.

## 4. Архитектура

```
UTF-16 source ─► source.py      BOM, строгий декодер UTF-16, позиции
              ─► lexer.py       токены (tokens.py)
              ─► parser.py      AST (ast_nodes.py), рекурсивный спуск
              ─► semantic.py    символы (symbol_table.py), типы (type_system.py),
                                граф наследования (inheritance.py)
              ─► flow.py        достижимость, возвраты, definite assignment
              ─► ir_builder.py  типизированный IR (ir.py)
              ─► codegen.py     C89 (имена: mangle.py) → output.h + output.c
              ─► build.py       gcc -std=c89 ... + runtime/*.c → .exe
```

Генерация C напрямую из AST не выполняется: генератор получает только `ir.Program`.

| Модуль | Ответственность |
|--------|-----------------|
| `compiler/main.py` | CLI, pipeline, коды завершения |
| `compiler/source.py` | чтение файла, BOM, строгий UTF-16, строки и столбцы |
| `compiler/tokens.py`, `lexer.py` | токены и лексер |
| `compiler/ast_nodes.py`, `parser.py` | AST и парсер |
| `compiler/symbol_table.py` | символы классов, интерфейсов, методов, полей, локальных переменных; вложенные области |
| `compiler/type_system.py` | структурные типы и **все** правила типизации: операции, присваивание, классификация приведений |
| `compiler/inheritance.py` | дерево подобъектов, разрешение полей и методов, правило переопределения D5, диспетчеризация Object, пути к предкам |
| `compiler/semantic.py` | проверки п. 17 ТЗ, аннотирование AST |
| `compiler/flow.py` | недостижимый код, обязательный return, definite assignment |
| `compiler/ir.py`, `ir_builder.py` | IR и его построение |
| `compiler/mangle.py`, `codegen.py` | имена C и генерация C89 |
| `compiler/build.py` | сборка (отдельная команда) |
| `compiler/errors.py` | категории диагностик и форматирование |
| `runtime/runtime.h` | API runtime для сгенерированного кода |
| `runtime/rt_core.c` | объекты, метаданные, приведения, `instanceof`, API Object, массивы, ошибки |
| `runtime/rt_long.c` | 64-битные целые на чистом C89 |
| `runtime/rt_num.c` | арифметика int, IEEE helpers, форматирование чисел как в Java |
| `runtime/rt_string.c` | строки UTF-16, вывод значений |
| `runtime/rt_math.c` | `Math` |
| `runtime/rt_gc.c` | переносимая часть mark-and-sweep |
| `runtime/rt_gc_win.c` | **платформенный модуль GC**: границы стека, сброс регистров |
| `runtime/rt_platform_win.c` | **платформенный модуль ввода-вывода**: UTF-16 argv, вывод |
| `runtime/rt_main.c` | C-функция `main` |

**IR.** Управление структурное (`Block`, `If`, `Loop`, `Break`, `Continue`, `Return`).
Выражения линеаризованы в трёхадресные инструкции над типизированными переменными, поэтому
порядок вычисления слева направо задан явно и не зависит от неуказанного в C порядка
вычисления аргументов. Каждая инструкция несёт типы операндов и результата, целевые символы,
способ вызова (`CallVirt` — VTable представления, `CallIface` — itable, `CallObj` — правило
Object, `CallDirect` — статически выбранная реализация, `CallInit` — конструктор родителя,
`CallBuiltin`), путь к подобъекту (`GetField.path`, `RefCast.path`) и вид приведения
(`RefCast.kind`). Для каждого динамического класса IR содержит дерево подобъектов, VTable
каждого подобъекта с выбранной реализацией каждого слота, itables и разрешение методов Object.

## 5. Поддерживаемый язык

- Классы: поля, методы, конструкторы и их перегрузка, `new`, `this`, `abstract`, `final`.
  Модификаторы доступа `public`, `protected`, `private`, package-private.
- Множественное наследование классов `class C extends A, B implements I, J` (§6).
- Интерфейсы с абстрактными методами, наследование и множественное наследование
  интерфейсов, `instanceof` и явные приведения к интерфейсам.
- Восемь примитивных типов, `String`, одномерные массивы любых поддерживаемых типов.
- Выражения: `+ - * / %`, `== != < > <= >=`, `&& || !`, унарные `+ -`, `++ --`, `?:`,
  приведения, `instanceof`, доступ к полям, вызовы, индексация, `= += -= *= /= %=`,
  `& | ^ ~`, `<< >> >>>`. Приоритеты и ассоциативность как в Java.
- Операторы: блоки, `if`/`else`, `while`, классический `for`, foreach по массиву, `break`,
  `continue`, `return`.
- Точка входа: `public static void main(String[] args)`.
- Встроенные средства: `System.out.print/println`, `String.valueOf`, `Math.*`, API Object и
  String (§10).

**Не поддерживаются** (диагностируются как ошибки): пакеты и `import`, статические поля и
методы (кроме `main`), обобщённые типы, вложенные и анонимные классы, лямбды, исключения
(`try/throw`), `do`, `switch`, метки, многомерные массивы и массивы массивов, литералы
массивов, `this(...)`, `final` у локальных переменных и параметров, `&= |= ^= <<= >>= >>>=`,
восьмеричные и двоичные литералы, `_` в числах, шестнадцатеричные вещественные литералы,
блоки инициализации, `.class`.

## 6. Множественное наследование и единый Object

### 6.1. Дерево подобъектов

Для класса K строится дерево: корень K, дети — деревья непосредственных родителей в порядке
объявления, **кроме Object**. Повторяющийся обычный предок встречается в дереве несколько раз:
это отдельные подобъекты, ромб их не объединяет. Object в дерево не входит: у полного объекта
ровно один подобъект Object, и это его заголовок.

```
class X { int f; }        class A extends X     class B extends X     class C extends A, B

полный объект C:  [ Object-заголовок | C: vt | A: vt [ X: vt, f ] | B: vt [ X: vt, f ] | поля C ]
                     один на объект      ветвь A, свой X              ветвь B, свой X
```

### 6.2. Поля

Сначала ищется собственное поле класса, затем поля родительских ветвей слева направо в
глубину. При совпадении имён выбирается поле первого родителя. `private`-поля родителей не
наследуются. Запись `obj.P.f` начинает поиск с подобъекта непосредственного родителя `P`.
Квалификаторы можно цеплять: `obj.A.X.f`.

### 6.3. Методы

Наборы перегрузок объединяются из всех ветвей. Для одинаковой сигнатуры из нескольких ветвей
обычный вызов берёт реализацию первого родителя; это не ошибка.

**Переопределение (решение D5).** Объявление `m` в классе K заменяет ровно ту реализацию,
которую вызвал бы `k.m()` без этого объявления. Это первая ветвь, где есть сигнатура, при
обходе слева направо в глубину. Остальные ветви сохраняют собственную диспетчеризацию и
собственные VTable. Формально (`inheritance.Hierarchy.effective`): для подобъекта по пути `p`
в объекте D слот `s` сначала указывает на `p · res(T, s)`. Затем для каждого объемлющего
подобъекта `e` (от ближнего к корню), класс которого объявляет `s`: если `e · inh(K, s)`
совпадает с текущим местом, местом становится `e`.

Следствие: если абстрактный `m()` есть в двух ветвях, одно объявление закрывает только одну
из них. Класс остаётся абстрактным, и компилятор сообщает, какой подобъект не реализован.
Final-метод нельзя переопределить ни в одной ветви.

### 6.4. Методы Object (п. 12.4, решение D6)

`toString()` и `equals(Object)` всегда диспетчеризуются от полного динамического объекта,
через ссылку любого статического типа. Если динамический класс объявил метод, берётся его
реализация. Иначе берётся первый родитель, в ветви которого есть переопределение; иначе
базовая реализация Object. `getClass()` — final. `super.P.toString()` вызывает реализацию
ветви P статически.

### 6.5. Конструкторы (D7)

Конструкторы всех непосредственных родителей вызываются явно, первыми операторами, строго в
порядке объявления: `super.A(...); super.B(...);`. Порядок инициализации такой:

1. выделение памяти и обнуление;
2. VTable всех подобъектов выставляются для итогового класса (I11);
3. значения по умолчанию;
4. ветви родителей по порядку, каждая полностью (инициализаторы полей и тело);
5. инициализаторы полей текущего класса;
6. тело конструктора.

Автоматический конструктор без аргументов создаётся только для класса без `extends`.

### 6.6. Приведения и `instanceof`

| Откуда → куда | Компиляция | Выполнение |
|---------------|------------|------------|
| класс S → предок T (≠ Object) | один путь — OK; несколько — **ошибка** (неоднозначный предок) | сдвиг указателя |
| любая ссылка → Object | всегда однозначно | переход к заголовку |
| класс S → потомок T | OK | поиск T среди объемлющих подобъектов |
| класс → неродственный класс | **ошибка** (обход: `(B)(Object)a`) | — |
| Object/интерфейс → класс T | OK | T должен встречаться в объекте ровно один раз |
| класс/интерфейс → интерфейс J | final-класс, не реализующий J, — ошибка | ближайший объемлющий подобъект, реализующий J |
| Object ↔ String/массив | массивы совместимы только при точном совпадении типа элемента | проверка класса |

`x instanceof T` истинно тогда и только тогда, когда `(T)x` успешно и `x != null`.
Неоднозначность, видимая только во время выполнения (у объекта два подобъекта X, а
статический тип — Object), даёт `instanceof → false`, а приведение — `ClassCast`.

### 6.7. Интерфейсы

Если `A implements I`, то и `C extends A` реализует I (D9). Одинаковые сигнатуры из
нескольких интерфейсов — одна обязанность, одна реализация удовлетворяет всем. Интерфейсная
ссылка указывает на подобъект-представление. Вызов идёт через отдельную таблицу itable этого
представления; она не смешивается с VTable. `(I)(B)c` вызывает реализацию ветви B.

## 7. Типы и отсутствие неявных преобразований

Неявных преобразований нет нигде: в числовых операциях, присваиваниях, аргументах,
возвращаемых значениях, тернарном операторе, между ссылочными типами (в том числе к родителю
и к интерфейсу). Единственное исключение — `null` совместим с любым ссылочным типом.

```java
long a = 5;          // ошибка: нужно 5L или (long) 5
byte b = (byte) 5;   // целый литерал имеет тип int
A x = c;             // ошибка, если c: C; нужно (A) c
String s = "n=" + String.valueOf(n);   // конкатенация только String + String
```

- Операнды арифметических, битовых операций и сравнений должны иметь одинаковый тип.
  Результат имеет тот же тип: `byte + byte → byte` с переполнением по модулю 2⁸ (I1).
- Правый операнд сдвига имеет тот же тип, что левый (I2). Дистанция маскируется `&31` /
  `&63`.
- `&&`, `||`, `!` и условия `if`/`while`/`for`/`?:` принимают только `boolean`. Операции
  `& | ^` также определены для `boolean`.
- `==` для ссылок требует одинаковых статических типов или `null` и сравнивает идентичность.
- Перегрузка выбирается по точному совпадению типов. Если подходят несколько вариантов
  (например, при аргументе `null`), это ошибка неоднозначности.

**Целые.** Модульная арифметика как в Java, без неопределённого поведения C: вычисления идут
над беззнаковыми значениями, деление усекает к нулю, `MIN / -1 == MIN`, остаток имеет знак
делимого. `long` эмулируется двумя 32-битными половинами (D1), поскольку в C89 нет
64-битного целого типа.

**Вещественные.** Используются аппаратные IEEE 754 binary32/binary64 (SSE2; GCC сообщает
`__GCC_IEC_559 == 2`, `__FLT_EVAL_METHOD__ == 0`). Места, где C89 допускает UB, обрабатываются
helper-функциями: деление на ноль (±Infinity, NaN), остаток по правилам Java, преобразования
NaN → 0 и с насыщением, `double → float` вне диапазона. Литерал `float` округляется точно,
а не через `double`.

## 8. Модель памяти и представление объектов

```c
typedef struct rt_object { rt_class *cls; unsigned long id; int mark; } rt_object;  /* единый Object */
struct js_T { const rt_vtbl_hdr *vt; struct js_P1 p_P1; struct js_P2 p_P2; /* поля T */ };
struct jf_D { rt_object hdr; struct js_D top; };                                    /* полный объект */
```

- Заголовок `rt_object` — единственный подобъект Object. Он хранит динамический класс,
  номер аллокации (для `Object.toString`) и GC-метку.
- Каждый подобъект класса начинается с указателя на VTable своей ветви. Для каждой пары
  (динамический класс, путь подобъекта) генерируется отдельная статическая VTable. Слот,
  реализованный в другом подобъекте, указывает на thunk, который сдвигает `self` на
  константу `offsetof`.
- Заголовок VTable хранит смещение до заголовка объекта, индекс подобъекта и список itables.
- Ссылка типа «класс T» указывает на подобъект `js_T`. Ссылки типов Object, String,
  массивов и `Class` указывают на заголовок. Интерфейсная ссылка указывает на
  подобъект-представление.
- Метаданные класса (`rt_class`) содержат имя, размер, все подобъекты (класс, смещение,
  объемлющий подобъект), смещения ссылочных полей для GC и реализации `toString`/`equals`
  по правилу 12.4.
- Массив: заголовок, длина, данные с выравниванием 8. Строка: заголовок, длина, символы
  UTF-16 в том же блоке. Строковые литералы и объекты `Class` статические, вне кучи;
  одинаковые литералы — один объект.
- Значения по умолчанию: память обнуляется, ссылочные и вещественные поля и элементы
  дополнительно инициализируются явно.

## 9. Сборка мусора

- **Алгоритм:** mark-and-sweep. Полная сборка выполняется перед **каждой** аллокацией
  (объекты, массивы, строки, результаты конкатенации). Порогового механизма нет. Это
  намеренно медленная модель: время каждой аллокации пропорционально размеру живой кучи.
- **Куча:** блоки `calloc`, индекс блоков отсортирован по адресу. Поиск блока по любому
  адресу внутри него — бинарный поиск, поэтому указатели на подобъекты (внутрь объекта)
  удерживают объект.
- **Корни:** консервативное сканирование стека текущего потока, модуль `rt_gc_win.c`.
  - ABI: Microsoft x64.
  - Регистры: `setjmp` сохраняет callee-saved регистры (rbx, rbp, rsi, rdi, r12–r15,
    xmm6–xmm15) в `jmp_buf` в кадре сборщика. Caller-saved регистры по ABI не могут хранить
    значения, живые через вызов сборщика.
  - Границы: от локальной переменной вспомогательного кадра (вызов через `volatile`
    указатель, без встраивания) до `NtCurrentTeb()->NtTib.StackBase`. Стек растёт вниз.
    Шаг — 8 байт с выравниванием.
- **Обход кучи** точный: ссылочные поля по `ref_offsets`, элементы ссылочных массивов по виду
  элемента. Явный стек маркировки, поэтому глубокие и циклические структуры не вызывают
  рекурсию в C. Циклы освобождаются.
- **Требования к GCC:** все файлы собираются с `-O0` (так делает `compiler.build`).
  Генератор хранит каждое промежуточное ссылочное значение в именованной локальной
  переменной. При `-O0` GCC держит такие переменные в кадре стека и не создаёт производных
  указателей за пределами объекта. Более высокие уровни оптимизации не проверялись и не
  поддерживаются.
- **Многопоточность:** не поддерживается; сканируется только стек текущего потока.
- **Ложные удержания:** устаревшие слова в неинициализированных ячейках стека могут
  удерживать несколько мёртвых объектов. Это допустимое свойство консервативного GC
  (п. 13.2); тесты учитывают его с допуском.
- **Финализаторов нет.** При нехватке памяти выдаётся `OutOfMemory` и программа завершается
  с кодом 1.

## 10. Runtime: строки, вывод, Math, ошибки

**API Object** (одинаковые сигнатуры в семантике, IR и runtime): `String toString()`,
`boolean equals(Object)`, `Class getClass()` (final). У `Class` есть метод `String getName()`;
имена Java-совместимы: `C`, `java.lang.String`, `[I`, `[LC;`. `Object.toString` по умолчанию
возвращает `Имя@номер_аллокации_hex`. Поддерживается `new Object()`.

**String** — неизменяемый final-класс, внутреннее представление UTF-16:
`int length()`, `char charAt(int)`, `String substring(int begin, int end)` (диапазон
`[begin, end)` в кодовых единицах), `boolean equals(String)`, `boolean equals(Object)`,
конкатенация `+` и `+=` (null-операнд даёт `"null"`). `==` сравнивает ссылки.
Преобразование примитива в строку — только явное: `String.valueOf(x)` для восьми примитивов.

**Вывод.** `System.out.print`/`println` для `boolean`, `char`, `byte`, `short`, `int`,
`long`, `float`, `double`, `String`, `Object`; есть и `println()` без аргументов.
- Ссылки других типов печатаются через `(Object)x`; объект печатается через `toString()`
  единого Object.
- Форматы как в Java: `true`/`false`, `null`, `NaN`, `Infinity`, `-Infinity`, `-0.0`.
  Числа `float`/`double` выводятся по правилу `Float/Double.toString` JDK 19+: кратчайшее
  десятичное представление не короче 2 цифр, обычная запись при `10⁻³ ≤ |x| < 10⁷`, иначе
  `d.dddE±n`.
- Перевод строки — `\r\n`, как `println` в Java на Windows.
- Поток вывода — UTF-8; в консоль символы идут через `WriteConsoleW`. Непарный суррогат
  выводится как U+FFFD.

**Аргументы командной строки** берутся в UTF-16 через `GetCommandLineW` +
`CommandLineToArgvW`; имя программы в `args` не входит.

**Math:** `abs`, `min`, `max` для `int`, `long`, `float`, `double`; `sqrt`, `pow`, `sin`,
`cos` для `double`; константы `Math.PI`, `Math.E`. Особые случаи Java (NaN, ±0.0,
бесконечности, `pow(1, NaN)`) обрабатываются явно. `sqrt` округляется корректно, а `sin`,
`cos`, `pow` берутся из UCRT и могут отличаться от `StrictMath` в последнем бите.

**Runtime errors** выводятся в stderr после сброса stdout, код завершения 1:

```
Runtime error [NullPointer]: null dereference
  at Main.java:12:9 in Main.main(String[])
```

Виды: `NullPointer`, `ArrayIndexOutOfBounds` (в том числе индексы строк), `DivisionByZero`,
`ClassCast`, `ArrayStore`, `OutOfMemory`, `InvalidRuntimeType`, `NegativeArraySize`.
Исключения Java не поддерживаются.

## 11. Грамматика (EBNF)

```ebnf
CompilationUnit = { TypeDecl } EOF ;
TypeDecl        = ClassDecl | InterfaceDecl ;
ClassDecl       = { "public" | "abstract" | "final" } "class" Ident
                  [ "extends" Ident { "," Ident } ] [ "implements" Ident { "," Ident } ]
                  "{" { Member } "}" ;
InterfaceDecl   = [ "public" ] "interface" Ident [ "extends" Ident { "," Ident } ]
                  "{" { { "public" | "abstract" } ResultType Ident "(" [ Params ] ")" ";" } "}" ;
Member          = FieldDecl | MethodDecl | ConstructorDecl ;
Modifier        = "public" | "protected" | "private" | "abstract" | "final" | "static" ;
FieldDecl       = { Modifier } Type VarDeclarator { "," VarDeclarator } ";" ;
MethodDecl      = { Modifier } ResultType Ident "(" [ Params ] ")" ( Block | ";" ) ;
ConstructorDecl = { Modifier } Ident "(" [ Params ] ")" Block ;
Params          = Type Ident { "," Type Ident } ;
VarDeclarator   = Ident [ "=" Expr ] ;
ResultType      = Type | "void" ;
Type            = ( PrimitiveType | Ident ) [ "[" "]" ] ;
PrimitiveType   = "byte" | "short" | "int" | "long" | "float" | "double" | "char" | "boolean" ;

Block           = "{" { BlockStmt } "}" ;
BlockStmt       = LocalVarDecl ";" | Statement ;
LocalVarDecl    = Type VarDeclarator { "," VarDeclarator } ;
Statement       = Block | ";"
                | "if" "(" Expr ")" Statement [ "else" Statement ]
                | "while" "(" Expr ")" Statement
                | "for" "(" [ ForInit ] ";" [ Expr ] ";" [ StmtExprList ] ")" Statement
                | "for" "(" Type Ident ":" Expr ")" Statement
                | "break" ";" | "continue" ";" | "return" [ Expr ] ";"
                | "super" "." Ident Arguments ";"              (* конструктор родителя *)
                | StmtExpr ";" ;
ForInit         = LocalVarDecl | StmtExprList ;
StmtExprList    = StmtExpr { "," StmtExpr } ;
StmtExpr        = Expr ;    (* присваивание, ++/--, вызов метода или new *)

Expr            = Conditional [ ( "=" | "+=" | "-=" | "*=" | "/=" | "%=" ) Expr ] ;
Conditional     = LogicalOr [ "?" Expr ":" Conditional ] ;
LogicalOr       = LogicalAnd { "||" LogicalAnd } ;
LogicalAnd      = BitOr { "&&" BitOr } ;
BitOr           = BitXor { "|" BitXor } ;
BitXor          = BitAnd { "^" BitAnd } ;
BitAnd          = Equality { "&" Equality } ;
Equality        = Relational { ( "==" | "!=" ) Relational } ;
Relational      = Shift { ( "<" | ">" | "<=" | ">=" ) Shift | "instanceof" Type } ;
Shift           = Additive { ( "<<" | ">>" | ">>>" ) Additive } ;
Additive        = Multiplicative { ( "+" | "-" ) Multiplicative } ;
Multiplicative  = Unary { ( "*" | "/" | "%" ) Unary } ;
Unary           = ( "+" | "-" | "++" | "--" ) Unary | UnaryNotPM ;
UnaryNotPM      = ( "!" | "~" ) Unary | CastExpr | Postfix ;
CastExpr        = "(" PrimitiveType [ "[" "]" ] ")" Unary | "(" Ident [ "[" "]" ] ")" UnaryNotPM ;
Postfix         = Primary { "." Ident [ Arguments ] | "[" Expr "]" } { "++" | "--" } ;
Primary         = Literal | "this" | "(" Expr ")" | Ident [ Arguments ]
                | "super" "." Ident "." Ident Arguments
                | "new" Ident Arguments | "new" ( PrimitiveType | Ident ) "[" Expr "]" ;
Arguments       = "(" [ Expr { "," Expr } ] ")" ;
Literal         = IntLit | LongLit | FloatLit | DoubleLit | CharLit | StringLit | "true" | "false" | "null" ;
```

Конструкция `( Имя )` считается приведением, если следующий токен может начинать операнд и
не является `+`/`-` (правило JLS). Парсер останавливается на первой синтаксической ошибке.

**Лексика.**
- Исходный файл — UTF-16 с обязательным BOM: `FF FE` означает LE, `FE FF` — BE. Без BOM,
  при нечётной длине или непарном суррогате выдаётся ошибка (D15).
- Комментарии `//` и `/* */`.
- Идентификаторы: первая кодовая точка категории `L*`, `Nl`, либо `_`, `$`; далее
  дополнительно `Nd`, `Mn`, `Mc`, `Pc`.
- Целые литералы: десятичные и `0x`, суффикс `L`/`l`. Проверяется диапазон;
  `-2147483648` и `-9223372036854775808L` допустимы только с унарным минусом.
- Вещественные литералы: десятичные с точкой и/или экспонентой, суффиксы `f F d D`.
  Переполнение и потеря до нуля — ошибка.
- Escape-последовательности `\n \t \\ \" \' \uXXXX` обрабатываются только внутри
  литералов, остальные — ошибка. Символьный литерал — одна кодовая единица UTF-16.

## 12. Имена в C

`mangle.py`: компонент имени экранируется (`[A-Za-z0-9]` без изменений, `_` → `_1`,
`$` → `_2`, не-ASCII → `_uXXXXXX`). Компоненты соединяются через `_0`, код типа
завершается `_9`; экранирование таких последовательностей не порождает, поэтому коллизии
невозможны. Префиксы: `js_`/`jf_` — структуры подобъекта и полного объекта, `jv_`/`ji_` — типы
VTable/itable, `jm_` — метод (`jm_Point_0move_0II`), `jc_`/`jn_` — init/allocate
конструктора, `jt_`/`jti_`/`jto_` — thunk-и, `jvt_`/`jit_` — экземпляры таблиц, `jd_`/`jda_`/`jdi_`
— метаданные, `rt_` — runtime. Поля структур имеют префиксы `f_`/`p_`, поэтому совпадение с
ключевыми словами C невозможно. Коды параметров: `B S I J F D C Z`, `L<имя>_9`, `A<элемент>`.
Значимая длина идентификаторов ограничивается GCC, а не минимальными пределами C89.

## 13. Диагностика

```
Test.java:4:14: error[type]: инициализация переменной a: несовместимые типы (неявных преобразований нет)
        long a = 5;
                 ^
  ожидается: long
  получено:  int
```

Категории: `lexical`, `syntax`, `type`, `semantic`, `codegen`. Сообщение содержит имя
файла, строку, столбец (в кодовых точках), фрагмент исходника и, где применимо, ожидаемый и
полученный тип. Lexer и parser останавливаются на первой ошибке. Семантический анализ
собирает все ошибки и не допускает построения IR, если они есть. Внутренняя ошибка
компилятора выводится как `internal compiler error` (traceback — с `--debug`) и
отличается кодом завершения 3.

Семантика проверяется на этапе компиляции:
- объявления, повторные объявления, разрешение имён, циклы наследования;
- доступ, override (тип результата, сужение доступа), final, abstract, реализация
  интерфейсов, конструкторы родителей;
- перегрузка по точному совпадению, типы операций, присваивания, возвраты;
- неоднозначные подобъекты, приведения, `instanceof`, массивы;
- недостижимый код, отсутствие return, чтение неинициализированной переменной.

## 16. Ограничения

- Только Windows x86-64 и GCC MinGW-w64. GC однопоточный и требует `-O0`; другие уровни
  оптимизации не проверены.
- Производительность намеренно низкая: GC перед каждой аллокацией — O(живая куча) на каждый
  `new`, а `long` эмулируется.
- Размер одного объекта или массива ограничен `size_t`; число элементов массива — `int`.
- **Final-поля:** присваивание разрешено только в конструкторах класса-владельца (через
  `this`/неявный `this`) и только если у поля нет инициализатора. Однократность присваивания
  и обязательность инициализации во всех конструкторах (правила JLS для blank final) **не
  проверяются**.
- **Константные выражения** для анализа достижимости: литералы и операции над
  `int`/`long`/`char`/`boolean`. Вещественные константы не вычисляются, поэтому, например,
  код после `while (1.0 < 2.0) { }` не считается недостижимым, в отличие от Java.
- **Definite assignment** упрощён и консервативен. Присваивания в теле цикла не учитываются
  для секции обновления `for`; некоторые корректные по JLS программы могут быть отвергнуты.
- `sin`, `cos`, `pow` берутся из UCRT, возможна разница с `StrictMath` в последнем бите.
  Для `float` при поиске кратчайшего представления возможен крайне редкий эффект двойного
  округления (`strtod` → `float`).
- Консервативный GC может удерживать несколько недостижимых объектов из-за устаревших слов
  в стеке.
- Предполагается порядок байтов little-endian (`rt_nan`, `rt_signbit`) и представление
  нулевого указателя всеми нулевыми битами (обнулённая память). Ссылочные и вещественные
  поля дополнительно инициализируются явно.
