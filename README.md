# Учебный компилятор подмножества Java в ISO C99

Компилятор на Python 3.10+ переводит программы на подмножестве Java в переносимый исходный
код ISO C99. Сгенерированный код собирается вместе с runtime-библиотекой на C99 любым
компилятором C99 на любой платформе с нужными типами (см. §19).

Это полноценный компилятор: лексический, синтаксический и семантический анализ (со
сворачиванием констант), анализ потока управления, типизированное промежуточное
представление (IR), анализ живости ссылок, генерация C99 и runtime с точной сборкой мусора
Mark-and-Sweep. Язык намеренно строже Java: одиночное наследование классов, множественное
наследование интерфейсов, единый `Object`, полный запрет неявных преобразований, `char` —
скалярное значение Unicode, исходники и строки — UTF-8.

Текущая версия — **v2 (C99)**. Предыдущая версия (ANSI C89, Windows x86-64, множественное
наследование классов, консервативный GC) сохранена без изменений в `history/v1-c89/` (§20).

## 1. Требования и установка

| Компонент | Требование |
|-----------|------------|
| Python | 3.10 или новее (проверено на 3.12.10). Только стандартная библиотека, сторонних зависимостей нет |
| Компилятор C | любой компилятор ISO C99. Скрипт сборки по умолчанию вызывает `gcc` с GCC/Clang-совместимыми опциями; другой компилятор задаётся `--cc`. Проверено: GCC 16.2.0 (MinGW-w64, UCRT) |
| Платформа | любая, где есть `int8_t`…`int64_t`, `uint8_t`…`uint64_t`, `uintptr_t`, IEEE 754 binary32/binary64 и `FLT_EVAL_METHOD == 0` (§19) |

Установка не нужна: достаточно скопировать каталог проекта. Все команды запускаются из
корня проекта.

Модули стандартной библиотеки Python: `fractions` — точное округление вещественных
литералов и сворачивание констант, `struct` — битовые образы IEEE 754, `subprocess` —
вызов компилятора C, `argparse` — командная строка.

## 2. Запуск: генерация C и сборка C99

Генерация C и компиляция C — два отдельных этапа.

**Генерация C:**

```bash
python -m compiler.main examples/Shapes.java -o shapes.c
```

Команда создаёт `shapes.c` и `shapes.h`. Опции:

| Опция | Назначение |
|-------|------------|
| `-o NAME.c` | имя выходного файла (`.h` создаётся рядом) |
| `--out-dir DIR` | каталог для выходных файлов |
| `--main Class` | класс с точкой входа, если в наборе исходников их несколько |
| `--debug` | traceback для внутренних ошибок компилятора |

Можно передать несколько исходных файлов: они образуют единый набор исходников с общей
таблицей типов. Встроенная прелюдия (`Throwable`, `Exception`, `RuntimeException`, §9)
компилируется вместе с ними автоматически.

**Сборка исполняемого файла:**

```bash
python -m compiler.build shapes.c -o shapes.exe --opt 2
```

Эквивалентная команда:

```bash
gcc -std=c99 -pedantic-errors -Wall -Wextra -O2 -I runtime -I . shapes.c runtime/*.c -o shapes.exe -lm
```

| Опция `compiler.build` | Назначение |
|------------------------|------------|
| `--opt 0\|1\|2\|3\|s` | уровень оптимизации (по умолчанию `0`). Корректность кода и GC от него не зависит |
| `--cc CC` | компилятор C99 с GCC-совместимыми опциями (`gcc`, `clang`, …) |
| `--win-args` | **необязательный** адаптер Windows: аргументы из UTF-16 (`CommandLineToArgvW`) вместо переносимого `rt_args.c`, кодовая страница консоли UTF-8 (прежняя восстанавливается при выходе); добавляет `-lshell32` |
| `--runtime DIR` | другой каталог runtime |

Сгенерированный код и runtime используют только стандартный C99: никаких расширений GCC,
`windows.h`, ассемблера, `setjmp`, предположений об ABI или направлении роста стека.
Платформенный код есть только в необязательном адаптере `runtime/adapters/win/`.

**Коды завершения компилятора:** `0` — успех, `1` — ошибки в исходной программе,
`2` — ошибка командной строки или ввода-вывода, `3` — внутренняя ошибка компилятора.
**Код завершения программы:** `0` — нормальное завершение, `1` — runtime error или
неперехваченный `throw`.

## 4. Архитектура

```
UTF-8 source ─► source.py      строгий декодер UTF-8 (BOM необязателен), позиции
             ─► lexer.py       токены (tokens.py); идентификаторы только ASCII
             ─► parser.py      AST (ast_nodes.py), рекурсивный спуск
             ─► semantic.py    символы (symbol_table.py), типы (type_system.py),
                               наследование (inheritance.py), константы (constfold.py),
                               прелюдия Throwable (prelude.py)
             ─► flow.py        достижимость, возвраты, definite assignment
             ─► ir_builder.py  типизированный IR (ir.py)
             ─► liveness.py    живость ссылок, ClearRefs перед safepoints
             ─► codegen.py     C99 (имена: mangle.py) → output.h + output.c
             ─► build.py       cc -std=c99 ... + runtime/*.c → исполняемый файл
```

Генератор C получает только `ir.Program`, не AST.

| Модуль | Ответственность |
|--------|-----------------|
| `compiler/main.py` | CLI, pipeline, коды завершения |
| `compiler/source.py` | чтение файла, строгий UTF-8, отказ от UTF-16, строки и столбцы |
| `compiler/tokens.py`, `lexer.py` | токены и лексер |
| `compiler/ast_nodes.py`, `parser.py` | AST и парсер |
| `compiler/symbol_table.py` | символы классов, интерфейсов, методов, полей (в том числе static), локальных переменных |
| `compiler/type_system.py` | структурные типы и все правила типизации, классификация приведений и `instanceof` |
| `compiler/inheritance.py` | цепочка классов, замыкание интерфейсов, таблицы методов, слоты VTable, разрешение полей |
| `compiler/constfold.py` | вычисление константных выражений по правилам Java (int/long/float/double/char/boolean/String) |
| `compiler/prelude.py` | исходный текст прелюдии `Throwable`/`Exception`/`RuntimeException` |
| `compiler/semantic.py` | проверки ТЗ, аннотирование AST, константы, правила static, конструкторы |
| `compiler/flow.py` | недостижимый код, обязательный return, definite assignment |
| `compiler/ir.py`, `ir_builder.py` | IR и его построение |
| `compiler/liveness.py` | обратный анализ живости и прямой анализ «грязных» слотов; вставка `ClearRefs` |
| `compiler/mangle.py`, `codegen.py` | имена C и генерация C99 |
| `compiler/build.py` | сборка (отдельная команда) |
| `compiler/errors.py` | категории диагностик и форматирование |
| `runtime/runtime.h` | API runtime, проверки платформы (`#error`) |
| `runtime/rt_core.c` | встроенные классы, приведения, `instanceof`, API Object, массивы, runtime errors, `rt_throw` |
| `runtime/rt_gc.c` | точный Mark-and-Sweep: кадры корней, `globals`, реестр объектов |
| `runtime/rt_num.c` | арифметика int/long/char без UB C, IEEE helpers, форматирование чисел как в Java |
| `runtime/rt_string.c` | строки UTF-8 (индексы в кодовых точках), конкатенация, вывод значений |
| `runtime/rt_math.c` | `Math` |
| `runtime/rt_io.c` | вывод байтов UTF-8 в стандартные потоки C |
| `runtime/rt_args.c` | переносимый адаптер командной строки: argv в UTF-8 со строгой проверкой |
| `runtime/rt_main.c` | C-функция `main` |
| `runtime/adapters/win/rt_args_win.c` | **необязательный** адаптер Windows (UTF-16 argv) |

**IR.** Управление структурное (`Block`, `If`, `Loop`, `Break`, `Continue`, `Return`).
Выражения линеаризованы в трёхадресные инструкции над типизированными переменными, поэтому
порядок вычисления слева направо задан явно и не зависит от неуказанного в C порядка
вычисления операндов. Каждая инструкция знает типы операндов и результата, целевые символы
и способ вызова: `CallVirt` (слот VTable и класс-владелец слота), `CallIface` (itable),
`CallObj` (методы Object через ссылку любого типа), `CallDirect` (private, `super.m()`),
`CallCtor` (конструктор для `new` и `super(...)`), `CallBuiltin`. Обращение к полю — через
класс-владелец (`GetField.field.owner`), к static-полю — `GetStatic`/`SetStatic`,
инициализация класса — `ClassInit`. Инструкции, внутри которых может начаться сборка
мусора, помечены `safepoint`; перед ними `liveness.py` вставляет `ClearRefs`.

## 5. Поддерживаемый язык

- Классы: поля экземпляра и static-поля, методы, конструкторы и их перегрузка, `new`,
  `this`, `super(...)`, `super.поле`, `super.метод(...)`, `abstract`, `final`. Модификаторы
  доступа `public`, `protected`, `private`, package-private.
- Одиночное наследование классов `class C extends P implements I, J`; класс без `extends`
  наследует `Object`.
- Интерфейсы с абстрактными методами, множественное наследование интерфейсов,
  `instanceof` и явные приведения к интерфейсам.
- Восемь примитивных типов, `String`, одномерные массивы любых поддерживаемых типов.
- Выражения: `+ - * / %`, `== != < > <= >=`, `&& || !`, унарные `+ -`, `++ --`, `?:`,
  приведения, `instanceof`, доступ к полям, вызовы, индексация, `= += -= *= /= %=`,
  `& | ^ ~`, `<< >> >>>`. Приоритеты и ассоциативность как в Java.
- Операторы: блоки, `if`/`else`, `while`, классический `for`, foreach по массиву, `break`,
  `continue`, `return`, `throw`.
- `throws` в объявлениях методов и конструкторов (информативно, проверяется только, что это
  подклассы `Throwable`).
- Точка входа: `public static void main(String[] args)`.
- Встроенные средства: `System.out.print/println`, `String.valueOf`, `Math.*`, API Object,
  String, Class, Throwable (§9, §12).

**Не поддерживаются** (диагностируются как ошибки): пакеты и `import`, пользовательские
static-методы (кроме `main`), static-блоки и блоки инициализации, `try`/`catch`/`finally`,
обобщённые типы, вложенные, локальные и анонимные классы, лямбды и ссылки на методы, `enum`,
аннотации, `do`, `switch`, метки, многомерные массивы и массивы массивов, литералы массивов,
`this(...)`, `final` у локальных переменных и параметров, `&= |= ^= <<= >>= >>>=`,
восьмеричные и двоичные литералы, `_` в числах, шестнадцатеричные вещественные литералы,
`.class`, не-ASCII идентификаторы.

## 6. Типы, константы и запрет неявных преобразований

Неявных преобразований нет нигде: в числовых операциях, присваиваниях, аргументах,
возвращаемых значениях, тернарном операторе, между ссылочными типами — **в том числе к
родителю и к интерфейсу**. Единственное исключение — `null` совместим с любым ссылочным
типом.

```java
long a = 5;          // ошибка: нужно 5L или (long) 5
byte b = (byte) 5;   // целый литерал имеет тип int
Base x = d;          // ошибка, если d: Derived; нужно (Base) d
Object o = s;        // ошибка; нужно (Object) s
String t = "n=" + String.valueOf(n);   // конкатенация только String + String
```

- Операнды арифметических, битовых операций и сравнений должны иметь одинаковый тип,
  результат того же типа: `byte + byte → byte` с переполнением по модулю 2⁸.
- Правый операнд сдвига имеет тот же тип, что левый; дистанция маскируется `&31`/`&63`.
- `&&`, `||`, `!` и условия `if`/`while`/`for`/`?:` принимают только `boolean`; `& | ^`
  определены и для `boolean`.
- `==` для ссылок требует одинаковых статических типов или `null` и сравнивает
  идентичность.
- Перегрузка выбирается по точному совпадению типов; несколько подходящих вариантов
  (например, при аргументе `null`) — ошибка неоднозначности.

**Целые.** Модульная арифметика как в Java без неопределённого поведения C: вычисления
идут над беззнаковыми `uint32_t`/`uint64_t`, деление усекает к нулю, `MIN / -1 == MIN`,
остаток имеет знак делимого, деление на ноль — runtime error `DivisionByZero`. `long` —
`int64_t`.

**Вещественные.** IEEE 754 binary32/binary64 (`float`/`double` C). Места, где C допускает
UB или зависит от реализации, закрыты helper-функциями: деление на ноль (±Infinity, NaN),
остаток по правилам Java, преобразования NaN → 0 и с насыщением, `double → float` вне
диапазона. Литерал `float` округляется точно, а не через `double`; в C вещественные
константы выводятся в шестнадцатеричной записи (`0x1.8p+0`) или битовым образом, без
потери точности.

**char (решение N2).** `char` — скалярное значение Unicode: U+0000…U+10FFFF без суррогатов
U+D800…U+DFFF (в C — `uint32_t`). Арифметика над `char` разрешена; результат, не
являющийся скалярным значением, — runtime error `InvalidChar` (в константном выражении —
ошибка компиляции). То же для приведения к `char` из чисел.

```java
char c = '😀';                 // одно значение U+1F600
char z = (char) 0; z--;        // Runtime error [InvalidChar]
char s = (char) 0xD800;        // ошибка компиляции: не является Unicode scalar value
```

**Константы (решение N4).** Константные выражения вычисляются при компиляции по правилам
Java (`constfold.py`): литералы, операции над примитивами и `String`, приведения, `?:`,
имена `static final` полей и локальных переменных с константным инициализатором. Результат
`float` округляется до binary32 на каждом шаге; целочисленное деление на ноль не
сворачивается (остаётся runtime error). Константа подставляется в место использования
литералом: обращение к константе **не инициализирует** класс. Константные строки
интернированы: `"a" + "b" == "ab"` — `true`, как в Java. Константные условия учитываются
анализом достижимости (`while (K.DEBUG)` с `false` — недостижимый код).

## 7. Наследование: один родитель-класс, много интерфейсов

- У класса ровно один родитель-класс (`extends P`, по умолчанию `Object`); цепочка классов
  линейна, циклы и наследование от `final`, `String`, интерфейсов — ошибки.
- Интерфейсы образуют DAG: класс реализует любое число интерфейсов, интерфейс расширяет
  любое число интерфейсов; одинаковая сигнатура из нескольких интерфейсов — одно
  обязательство, разные типы результата — ошибка.
- Интерфейсы наследуются через классы: подкласс реализует интерфейсы всех предков.
- **Переопределение:** та же сигнатура, тот же тип результата, без сужения доступа; `final`
  -методы не переопределяются; `private`-методы не наследуются. Неабстрактный класс обязан
  реализовать все абстрактные методы (сообщение перечисляет недостающие); реализация метода
  интерфейса должна быть `public`.
- **Поля:** собственное поле скрывает одноимённое поле предка; `super.f` обращается к полю
  родителя; `private`-поля предков в потомке не видны.
- **Конструкторы.** Первым оператором может стоять `super(args)`; иначе неявно вызывается
  `super()`, и у родителя должен быть доступный конструктор без аргументов. Конструктор по
  умолчанию создаётся, если конструкторов нет. До вызова конструктора родителя нельзя
  обращаться к `this` (полям, методам) — ошибка «до вызова конструктора родителя».
  Порядок: конструктор родителя → инициализаторы полей класса в порядке объявления → тело.
  `this(...)` не поддерживается.
- **Методы Object** (`toString`, `equals`, `getClass`) вызываются через ссылку любого
  ссылочного типа, включая интерфейсы и массивы; `super.toString()` вызывает реализацию
  родителя (или Object). Виртуальный вызов из конструктора видит динамический класс (поля
  потомка ещё имеют значения по умолчанию, как в Java).
- **Приведения и `instanceof`:** к предку — без проверки во время выполнения (но
  обязательно явно); к потомку — проверка по цепочке классов (`ClassCast` при ошибке); к
  интерфейсу — проверка по таблице интерфейсов класса; к `String`, `Class` и массивам —
  точное совпадение класса (**ковариантности массивов нет**: `I[]` не является
  `Object[]`). Приведение между неродственными классами — ошибка компиляции с подсказкой
  `используйте (X)(Object)x`; приведение `final`-класса к интерфейсу, который он не
  реализует, — ошибка компиляции.

## 8. Статические поля и инициализация классов

**Объявление и доступ (решение N5).** Поддерживаются static-поля любых типов, с
инициализатором или без; `static final` поле обязано иметь инициализатор и не может
изменяться. Доступ — `ИмяКласса.поле` или простым именем внутри класса и его подклассов.
Обращение через экземпляр (`obj.f`, `this.f`) к static-полю запрещено, как и чтение поля
экземпляра через имя класса. Опережающая ссылка на поле в инициализаторе (`static int a =
b; static int b = 1;`) — ошибка, как в Java (`A.b` разрешено).

**Хранение.**
- Ссылочные static-поля лежат в массиве `void *globals[N]` (`const size_t globals_count =
  N`) — это корни GC. Константные строки инициализируются статически: `[i] = &jstr_k`.
- Примитивные static-поля — отдельные переменные C `jsv_<Класс>_0<поле>` со значением
  константы или нулём.

**Ленивая инициализация (решение N4)** по модели Java:
- у класса есть состояние `jcs_<C>` (`RT_CLS_UNINITIALIZED` → `INITIALIZING` →
  `INITIALIZED`) и функция `jci_<C>`: сначала инициализируется родитель, затем
  инициализаторы static-полей выполняются в порядке объявления;
- инициализацию запускают `new C(...)` (до вычисления аргументов) и обращение к
  неконстантному static-полю (инициализируется класс, где поле объявлено: `Q.p`, где `p`
  объявлено в `P`, инициализирует только `P`);
- создание массива `new C[n]` и обращение к константе класс не инициализируют;
- рекурсивная инициализация видит значения по умолчанию (как в Java);
- проверка не генерируется там, где класс заведомо инициализирован (код самого класса и
  его подклассов), и для классов, у которых нет неконстантных инициализаторов ни у них, ни
  у предков.

## 9. throw и Throwable

Иерархия исключений — исходный текст на подмножестве Java (`compiler/prelude.py`),
компилируемый вместе с программой:

```java
public class Throwable {
    private String message;
    public Throwable() { } public Throwable(String message) { this.message = message; }
    public String getMessage() { return message; }
    public String toString() { /* getClass().getName() [+ ": " + getMessage()] */ }
}
public class Exception extends Throwable { /* () и (String) */ }
public class RuntimeException extends Exception { /* () и (String) */ }
```

`getClass().getName()` для них возвращает `java.lang.Throwable`, `java.lang.Exception`,
`java.lang.RuntimeException`. Пользовательские исключения наследуются от любого из них.

`throw e;` требует выражения подкласса `Throwable` (или `null`) и завершает путь
выполнения для анализа потока. Перехвата нет: **неперехваченный throw (решение N6)**
сбрасывает stdout и выводит в stderr

```
Exception in thread "main" ИмяКласса: сообщение
  at Файл.java:строка:столбец in Класс.метод(типы)
```

где сообщение — результат виртуального `getMessage()` (строка `: сообщение` опускается,
если он вернул `null`); сообщение выводится целиком по длине, включая символы U+0000;
код завершения 1. `throw null` — runtime error `NullPointer`.
Внутренние runtime errors (§12) — отдельный механизм с форматом `Runtime error [...]`.

## 10. Модель памяти: ссылки void*, объекты, VTable

**Все ссылки в сгенерированном C — `void *`**, указывающие на заголовок объекта; типизация
обеспечивается компилятором, а не C. Это упрощает точные корни: слот кадра, элемент
`globals` и ссылочное поле — одно машинное слово `void *`.

```c
typedef struct rt_object { const rt_class *cls; uint64_t id; unsigned char mark; } rt_object;
struct jo_Base { rt_object hdr; void *f_title; };                 /* класс без родителя-пользователя */
struct jo_Circle { struct jo_Base base; jdouble f_r; };           /* потомок: родитель — префикс */
/* доступ к полю — через структуру класса-владельца: */
((struct jo_Base *)p)->f_title
```

- Заголовок `rt_object` — единственный «подобъект» Object: динамический класс, номер
  аллокации (для `Object.toString`) и метка GC.
- **VTable** — одна на класс, структура с префиксом родителя:
  `struct jv_C { struct jv_P base; /* слоты, впервые введённые в C */ }`, корень —
  `rt_vtbl_Object` (`toString`, `equals`). Экземпляр
  `static const struct jv_C jvt_C = { .base.base.m_x = jm_..., ... }` (designated
  initializers). Виртуальный вызов:
  `((const struct jv_Owner *)rt_vtable(r))->m_x(r, ...)`, где `Owner` — класс, впервые
  объявивший слот.
- **Интерфейсы:** для интерфейса `I` — структура таблицы `struct ji_I`, для каждого класса и
  реализуемого интерфейса — `static const struct ji_I jit_C_0I`; список пар (дескриптор
  интерфейса, таблица) хранится в метаданных класса и включает унаследованные интерфейсы.
  Вызов: `((const struct ji_I *)rt_itable(r, &jdi_I, loc))->m_x(r, ...)`.
- **Метаданные класса** `rt_class`: имя (Java-совместимое), родитель, размер, смещения
  ссылочных полей (`offsetof`) для GC, VTable, таблицы интерфейсов; для массивов — вид и
  размер элемента.
- Массив: заголовок, длина, данные с выравниванием для любого типа элемента. Строка:
  заголовок, длина в кодовых точках, длина в байтах, признак ASCII, байты UTF-8. Строковые
  литералы и объекты `Class` статические, вне кучи; одинаковые литералы — один объект.
- **Значения по умолчанию:** память обнуляется, а ссылочные, `boolean` и вещественные поля
  и элементы дополнительно инициализируются явно (`NULL`, `false`, `0.0`) — от
  представления нулевого указателя и `+0.0` ничего не зависит.

## 11. Точная сборка мусора: кадры rets, globals, safepoints

- **Алгоритм:** Mark-and-Sweep. Полная сборка выполняется перед **каждой** управляемой
  аллокацией (объекты, массивы, строки, результаты конкатенации). Порогового механизма нет:
  модель намеренно медленная, время аллокации пропорционально размеру живой кучи.
- **Корни точные, стек не сканируется:**
  - `globals[0 .. globals_count-1]` — ссылочные static-поля;
  - цепочка корневых кадров, начинающаяся с `rt_rets`.
- **Кадр (решение N1).** Каждая сгенерированная функция с ссылками заводит
  `void *jf[RT_FRAME_WORDS(k)]`: `jf[0]` — предыдущий кадр, `jf[1]` — статический
  дескриптор `{ root_count, "Класс.метод(типы)" }`, `jf[2..k+1]` — слоты ссылок,
  `jf[k+2]` — терминатор, указатель на сам кадр. Сборщик обходит кадр по `root_count` из
  дескриптора и проверяет терминатор на позиции, вычисленной по дескриптору; несовпадение
  — `CorruptedRootFrame`. Несбалансированный `rt_frame_pop` тоже обнаруживается.
- **Все ссылочные значения функции живут в слотах кадра** — параметры (копируются в
  пролог), локальные переменные и промежуточные значения выражений; в регистрах и
  C-переменных ссылки через safepoint не переносятся. Поэтому корни не зависят от ABI,
  регистров, направления роста стека и уровня оптимизации C: от `-O0` до `-O3`.
- **Safepoints и обнуление мёртвых слотов.** Safepoint — инструкция, внутри которой может
  произойти сборка: аллокация, вызов, инициализация класса, конкатенация, `throw`.
  `liveness.py` выполняет обратный анализ живости (с неподвижной точкой по циклам) и
  прямой анализ «грязных» слотов; перед каждым safepoint вставляется `ClearRefs`, который
  обнуляет слоты, содержащие уже мёртвые ссылки. Поэтому сборщик не удерживает
  недостижимые объекты, и **число живых объектов после сборки точно определено** —
  тесты проверяют его равенство, а не оценку.
- **Аргументы вызова** остаются в слотах вызывающей функции до конца вызова; результат
  вызова сразу записывается в слот.
- **Реестр объектов** — массив указателей, отсортированный по `uintptr_t`-образу адреса,
  бинарный поиск. Значение слота, не найденное в реестре, — статический объект (литерал,
  `Class`) и игнорируется.
- **Обход кучи** точный: ссылочные поля по `ref_offsets`, элементы ссылочных массивов по
  виду элемента; явный стек маркировки — глубокие и циклические структуры не вызывают
  рекурсии в C. Циклы освобождаются.
- `rt_gc_hook` — необязательный обработчик после каждой сборки (используется тестами для
  проверки точных счётчиков).
- Однопоточная модель; финализаторов нет; при нехватке памяти — `OutOfMemory`, код 1.

## 12. Runtime: строки UTF-8, вывод, аргументы, Math, ошибки

**API Object:** `String toString()`, `boolean equals(Object)`, `Class getClass()` (final).
`Class.getName()` даёт Java-совместимые имена: `C`, `java.lang.String`, `[I`, `[LC;`.
`Object.toString` по умолчанию — `Имя@номер_аллокации_hex`. Поддерживается
`new Object()`.

**String** — неизменяемый final-класс, внутреннее представление UTF-8, **длина и индексы
в кодовых точках**: `int length()`, `char charAt(int)`, `String substring(int, int)`,
`boolean equals(String)`, `boolean equals(Object)`, конкатенация `+`/`+=` (операнд `null`
даёт `"null"`). Для ASCII-строк индексация O(1). `==` сравнивает ссылки. Примитив в строку
— только явно: `String.valueOf(x)`.

**Вывод.** `System.out.print`/`println` для восьми примитивов, `String` и `Object`;
`println()` без аргументов. Поток — байты UTF-8 в `stdout`; перевод строки — `'\n'` в
текстовом потоке C, т. е. разделитель строк платформы. Форматы чисел как
`Float/Double.toString` JDK 19+: кратчайшее представление, обычная запись при
`10⁻³ ≤ |x| < 10⁷`, иначе `d.dddE±n`; `NaN`, `Infinity`, `-0.0`.

**Аргументы командной строки (решение N3).** Переносимый `rt_args.c` принимает argv как
UTF-8 и проверяет строго (overlong, суррогаты, > U+10FFFF, обрыв последовательности,
одиночные байты продолжения): ошибка — `Runtime error [InvalidArgument]`. Имя программы в
`args` не входит. В Windows, где argv приходит в кодовой странице ANSI, используется
необязательный адаптер `--win-args`: аргументы берутся в UTF-16 (непарный суррогат →
`InvalidArgument`), кодовая страница вывода консоли на время работы переключается на
UTF-8 и восстанавливается при любом завершении (обычном, ошибке runtime, неперехваченном
`throw`). Без адаптера символы вне ANSI-страницы заменяются системой на `?` ещё до
запуска программы, а байты, не образующие UTF-8, дают `InvalidArgument`.

**Math:** `abs`, `min`, `max` для `int`, `long`, `float`, `double`; `sqrt`, `pow`, `sin`,
`cos` для `double`; `Math.PI`, `Math.E`. Особые случаи Java (NaN, ±0.0, бесконечности,
`pow(1, NaN)`) обрабатываются явно; `sqrt` корректно округлён по IEEE, `sin`/`cos`/`pow` —
из `libm` платформы.

**Runtime errors** — в stderr после сброса stdout, код завершения 1:

```
Runtime error [NullPointer]: null dereference
  at Main.java:12:9 in Main.main(String[])
```

Виды: `NullPointer`, `ArrayIndexOutOfBounds` (в том числе индексы строк),
`DivisionByZero`, `ClassCast`, `ArrayStore`, `OutOfMemory`, `InvalidRuntimeType`,
`NegativeArraySize`, `InvalidChar`, `InvalidArgument`, `CorruptedRootFrame`.
`ArrayStore`, `InvalidRuntimeType` и `CorruptedRootFrame` — защитные проверки, которые
корректно типизированная программа не вызывает.

## 13. Грамматика (EBNF) и лексика

```ebnf
CompilationUnit = { TypeDecl } EOF ;
TypeDecl        = ClassDecl | InterfaceDecl ;
ClassDecl       = { "public" | "abstract" | "final" } "class" Ident
                  [ "extends" Ident ] [ "implements" Ident { "," Ident } ]
                  "{" { Member } "}" ;
InterfaceDecl   = [ "public" ] "interface" Ident [ "extends" Ident { "," Ident } ]
                  "{" { { "public" | "abstract" } ResultType Ident "(" [ Params ] ")" [ Throws ] ";" } "}" ;
Member          = FieldDecl | MethodDecl | ConstructorDecl ;
Modifier        = "public" | "protected" | "private" | "abstract" | "final" | "static" ;
FieldDecl       = { Modifier } Type VarDeclarator { "," VarDeclarator } ";" ;
MethodDecl      = { Modifier } ResultType Ident "(" [ Params ] ")" [ Throws ] ( Block | ";" ) ;
ConstructorDecl = { Modifier } Ident "(" [ Params ] ")" [ Throws ] Block ;
Throws          = "throws" Ident { "," Ident } ;
Params          = Type Ident { "," Type Ident } ;
VarDeclarator   = Ident [ "=" Expr ] ;
ResultType      = Type | "void" ;
Type            = ( PrimitiveType | Ident ) [ "[" "]" ] ;
PrimitiveType   = "byte" | "short" | "int" | "long" | "float" | "double" | "char" | "boolean" ;

Block           = "{" { BlockStmt } "}" ;
BlockStmt       = LocalVarDecl ";" | Statement ;
LocalVarDecl    = Type VarDeclarator { "," VarDeclarator } ;
Statement       = Block | ";"
                | "if" "(" Expr ")" Statement [ "else" Statement ]
                | "while" "(" Expr ")" Statement
                | "for" "(" [ ForInit ] ";" [ Expr ] ";" [ StmtExprList ] ")" Statement
                | "for" "(" Type Ident ":" Expr ")" Statement
                | "break" ";" | "continue" ";" | "return" [ Expr ] ";"
                | "throw" Expr ";"
                | "super" Arguments ";"        (* только первым оператором конструктора *)
                | StmtExpr ";" ;
ForInit         = LocalVarDecl | StmtExprList ;
StmtExprList    = StmtExpr { "," StmtExpr } ;
StmtExpr        = Expr ;    (* присваивание, ++/--, вызов метода или new *)

Expr            = Conditional [ ( "=" | "+=" | "-=" | "*=" | "/=" | "%=" ) Expr ] ;
Conditional     = LogicalOr [ "?" Expr ":" Conditional ] ;
LogicalOr       = LogicalAnd { "||" LogicalAnd } ;
LogicalAnd      = BitOr { "&&" BitOr } ;
BitOr           = BitXor { "|" BitXor } ;
BitXor          = BitAnd { "^" BitAnd } ;
BitAnd          = Equality { "&" Equality } ;
Equality        = Relational { ( "==" | "!=" ) Relational } ;
Relational      = Shift { ( "<" | ">" | "<=" | ">=" ) Shift | "instanceof" Type } ;
Shift           = Additive { ( "<<" | ">>" | ">>>" ) Additive } ;
Additive        = Multiplicative { ( "+" | "-" ) Multiplicative } ;
Multiplicative  = Unary { ( "*" | "/" | "%" ) Unary } ;
Unary           = ( "+" | "-" | "++" | "--" ) Unary | UnaryNotPM ;
UnaryNotPM      = ( "!" | "~" ) Unary | CastExpr | Postfix ;
CastExpr        = "(" PrimitiveType [ "[" "]" ] ")" Unary | "(" Ident [ "[" "]" ] ")" UnaryNotPM ;
Postfix         = Primary { "." Ident [ Arguments ] | "[" Expr "]" } { "++" | "--" } ;
Primary         = Literal | "this" | "(" Expr ")" | Ident [ Arguments ]
                | "super" "." Ident [ Arguments ]              (* поле или метод родителя *)
                | "new" Ident Arguments | "new" ( PrimitiveType | Ident ) "[" Expr "]" ;
Arguments       = "(" [ Expr { "," Expr } ] ")" ;
Literal         = IntLit | LongLit | FloatLit | DoubleLit | CharLit | StringLit | "true" | "false" | "null" ;
```

Конструкция `( Имя )` считается приведением, если следующий токен может начинать операнд и
не является `+`/`-` (правило JLS). Парсер останавливается на первой синтаксической ошибке.

**Лексика.**
- Исходный файл — строгий UTF-8; BOM `EF BB BF` допускается и пропускается. Файл в UTF-16
  (по BOM) отвергается с отдельным сообщением; некорректные последовательности (overlong,
  суррогаты, > U+10FFFF, обрыв) — ошибка с позицией.
- Идентификаторы — **только ASCII**: `[A-Za-z_$][A-Za-z0-9_$]*`, одиночный `_` запрещён.
  Не-ASCII буква в идентификаторе — ошибка «допустимы только ASCII»; Unicode разрешён в
  строковых и символьных литералах и комментариях.
- Комментарии `//` и `/* */`.
- Целые литералы: десятичные и `0x`, суффикс `L`/`l`; диапазон проверяется,
  `2147483648` и `9223372036854775808L` допустимы только под унарным минусом.
- Вещественные литералы: десятичные с точкой и/или экспонентой, суффиксы `f F d D`;
  переполнение и потеря до нуля — ошибка.
- Escape-последовательности `\n \t \\ \" \' \uXXXX`; `\uXXXX` с суррогатом — ошибка
  (символ вне BMP пишется непосредственно в UTF-8). Строковый литерал — последовательность
  кодовых точек; символьный литерал — одна кодовая точка (в том числе вне BMP).
- Столбцы в диагностике считаются в кодовых точках.

## 14. Имена в C

`mangle.py`: компонент имени экранируется (`[A-Za-z0-9]` без изменений, `_` → `_1`,
`$` → `_2`). Компоненты соединяются через `_0`, код типа параметров завершается `_9`;
экранирование таких последовательностей не порождает, поэтому коллизии невозможны.

| Префикс | Сущность |
|---------|----------|
| `jo_C` | структура объекта класса |
| `jv_C`, `jvt_C` | тип и экземпляр VTable |
| `ji_I`, `jit_C_0I`, `jie_C`, `jdi_I` | тип таблицы интерфейса, экземпляр, список таблиц класса, дескриптор интерфейса |
| `jm_C_0m_0sig` | метод (`jm_Point_0move_0II`) |
| `jc_C_0sig`, `jn_C` | конструктор, выделение объекта со значениями по умолчанию |
| `jci_C`, `jcs_C` | инициализация класса и её состояние |
| `jsv_C_0f` | примитивное static-поле |
| `jd_C`, `jda_`, `jro_C` | метаданные класса, массива, смещения ссылочных полей |
| `jfd_N` | дескриптор корневого кадра |
| `jstr_N`, `jstrd_N` | строковый литерал и его байты |
| `m_`, `f_` | слот VTable/itable и поле структуры (исключают совпадение с ключевыми словами C) |
| `rt_` | runtime |

Коды типов: `B S I J F D C Z`, `L<имя>_9`, `A<элемент>`. Локальные переменные — `v<id>_0имя`
или временные `t<id>`; ссылочные переменные живут в слотах `jf[i]`. Сгенерированный текст —
чистый ASCII: строковые данные выводятся массивами байтов, вещественные константы —
шестнадцатеричными литералами или битовыми образами.

## 15. Диагностика

```
Test.java:4:14: error[type]: инициализация переменной a: несовместимые типы (неявных преобразований нет)
        long a = 5;
                 ^
  ожидается: long
  получено:  int
```

Категории: `lexical`, `syntax`, `type`, `semantic`, `codegen`. Сообщение содержит имя
файла, строку, столбец (в кодовых точках), фрагмент исходника и, где применимо, ожидаемый и
полученный тип. Lexer и parser останавливаются на первой ошибке; семантический анализ
собирает все ошибки и не допускает построения IR, если они есть. Внутренняя ошибка
компилятора — `internal compiler error` (traceback с `--debug`), код завершения 3.

Проверяется при компиляции:
- объявления, повторные объявления, разрешение имён, циклы наследования классов и
  интерфейсов, наследование от `final`/встроенных классов;
- доступ, override (тип результата, сужение доступа, `final`), abstract, реализация
  интерфейсов, конструкторы родителей, положение `super(...)`, `this` до вызова
  конструктора родителя;
- правила static: доступ через экземпляр, `static final` без инициализатора, изменение
  `final`, опережающие ссылки, `this` в статическом контексте;
- `throw`/`throws` только для `Throwable`;
- перегрузка по точному совпадению, типы операций, присваивания, возвраты, приведения,
  `instanceof`, массивы;
- константные выражения (в том числе недопустимый `char`);
- недостижимый код, отсутствие return, чтение неинициализированной переменной.

## 17. Согласованные решения

| № | Решение |
|---|---------|
| N1 | Статический дескриптор кадра: `root_count`, имя функции; терминатор-ссылка на кадр, проверяемый по позиции из дескриптора; обход кадра по `root_count` |
| N2 | Арифметика над `char` разрешена; результат вне скалярных значений Unicode — runtime error `InvalidChar`, в константном выражении — ошибка компиляции |
| N3 | Основной runtime платформенно-независим, argv и вывод — UTF-8; адаптер Windows необязателен; некорректный UTF-8 в аргументах — `InvalidArgument` |
| N4 | Ленивая инициализация классов как в Java, константы времени компиляции, сворачивание констант, интернирование строк |
| N5 | static-поле — `Класс.поле` или простое имя в классе и подклассах; доступ через экземпляр запрещён |
| N6 | Неперехваченный throw: `Exception in thread "main" Имя: сообщение` + позиция, код 1; внутренние runtime errors — отдельный механизм |
| N7 | Все этапы выполняются без промежуточных остановок, после каждого — тесты, отчёт в конце |

Дополнительно согласовано: `this(args)` не поддерживается, `super.field` поддерживается;
на платформах без точных целых типов или IEEE 754 допустима диагностическая ошибка сборки;
тестирование на `-O0` и `-O2`, корректность не зависит от оптимизаций; перед каждым
safepoint обнуляются слоты мёртвых ссылок, счётчики живых объектов после сборки проверяются
на точное равенство; генерируется максимально переносимый ISO C99 без обязательной
зависимости от Windows, GCC, ABI и направления роста стека.

Интерпретации, принятые в реализации:
- `byte + byte → byte`; правый операнд сдвига того же типа; `& | ^` для `boolean`;
  `==` для ссылок одинаковых типов.
- `private`-члены предков не наследуются; интерфейс не может переобъявлять методы Object.
- Обращение к static-полю через подкласс (`Q.p`) инициализирует только объявивший класс.
- Константа времени компиляции — `static final` поле или локальная переменная с
  константным инициализатором; циклические зависимости констант константами не считаются.
- `getMessage()` для сообщения неперехваченного throw вызывается виртуально (учитывает
  переопределение); если он возвращает `null`, выводится только имя класса.
- Ковариантности массивов нет: тип массива во время выполнения совпадает со статическим.

## 18. Отклонения от стандартной Java

- **`char` — скалярное значение Unicode** (до U+10FFFF), а не кодовая единица UTF-16;
  `String.length()`, `charAt`, `substring` работают в кодовых точках; значения-суррогаты
  недопустимы (`InvalidChar`).
- **Нет неявных преобразований**, включая расширение примитивов и приведение к родителю
  или интерфейсу; `+` конкатенирует только `String + String`.
- **Нет перехвата исключений:** `throw` завершает программу; трассировка — одна позиция
  (место `throw`); нет `cause`, `printStackTrace`, `ExceptionInInitializerError`. Runtime
  errors не являются исключениями Java и не проходят через `Throwable`.
- Нет пользовательских static-методов (кроме `main`) и static-блоков.
- Нет ковариантности массивов; `ArrayStoreException` невозможен в типизированной
  программе.
- `Object.toString()` использует номер аллокации вместо `hashCode()` (метода `hashCode`
  нет).
- `println` выводит разделитель строк платформы через текстовый поток C.
- `sin`, `cos`, `pow` из `libm` могут отличаться от `StrictMath` в последнем бите.

## 19. Ограничения и требования к платформе

- **Требования к платформе** (проверяются в `runtime.h`/`rt_gc.c` директивой `#error`):
  `int8_t`…`int64_t` и `uint8_t`…`uint64_t`; `uintptr_t` (реестр объектов упорядочен по
  образу адреса — сравнение указателей на разные объекты в C не определено);
  `float`/`double` — IEEE 754 binary32/binary64 (`FLT_RADIX`, `*_MANT_DIG`, `*_MAX_EXP`,
  `*_MIN_EXP`); `FLT_EVAL_METHOD == 0` (без избыточной точности; например, на x86 нужен
  SSE2, а не x87). Предполагается одинаковый порядок байтов у целых и вещественных типов
  (битовые образы через `memcpy` в `rt_dbits`/`rt_fbits`).
- Производительность намеренно низкая: GC перед каждой аллокацией — O(живая куча) на
  каждый `new` и каждую конкатенацию.
- Однопоточная модель исполнения.
- Размер объекта или массива ограничен `size_t`; число элементов массива — `int`.
- **Final-поля:** присваивание разрешено только в конструкторах класса-владельца и только
  если у поля нет инициализатора; однократность присваивания и обязательность
  инициализации во всех конструкторах (правила JLS для blank final) не проверяются.
- **Definite assignment** упрощён и консервативен; некоторые корректные по JLS программы
  могут быть отвергнуты.
- Для `float` при поиске кратчайшего десятичного представления возможен крайне редкий
  эффект двойного округления (`strtod` → `float`).
- Адаптер `--win-args` использует `windows.h` и проверен только с MinGW-w64.

## 20. История: версия v1 (C89)

Каталог `history/v1-c89/` содержит полный снимок первой версии: компилятор, runtime,
тесты, примеры, исходное ТЗ `master_prompt_java_to_c89.txt` и README. Отличия v1 от
текущей версии:

| v1 (C89) | v2 (C99, текущая) |
|----------|-------------------|
| ANSI C89, Windows x86-64, GCC MinGW-w64, `-O0` обязателен | переносимый ISO C99, любой компилятор и уровень оптимизации |
| исходники UTF-16 с BOM, Unicode-идентификаторы | строгий UTF-8, идентификаторы ASCII |
| `char`/`String` в кодовых единицах UTF-16 | `char` — скалярное значение Unicode, строки UTF-8 в кодовых точках |
| множественное наследование классов, подобъекты, `super.A(...)` | одиночное наследование классов, `super(...)`, множественное — только интерфейсов |

| консервативный GC: сканирование стека, `setjmp`, TIB | точный GC: кадры `rt_rets`, `globals`, обнуление мёртвых слотов |
| `long` эмулировался двумя 32-битными половинами | `int64_t` |
| нет static-полей и исключений | static-поля, ленивая инициализация, константы, `throw` и `Throwable` |

Версия v1 больше не развивается; действующей спецификацией является
`master_prompt_java_to_c99.txt`.
